# 食刻 FitBite 首版设计与实施计划

目标：为健身新手提供中文、手机电脑适配的食物摄入记录工具，最终发布到 GitHub 与 GitHub Pages。

方案比较：改造 NutriLens 可复用离线识别但模型链路复杂；NutriNutri 基于 Flutter，构建部署较重；本次选择独立、无构建的 HTML/CSS/ES Modules 实现，使用可选浏览器端开源模型，方便 Pages 部署。用户已选择网页版，其余技术选择由开发者负责。

设计：浅灰绿色工作区、墨绿色侧栏、鲜绿色主操作、橙色热量强调；中文系统字体，8px 间距，20px 卡片圆角，轻阴影。桌面双栏、手机单栏；所有操作可键盘访问。初始记录为空，示例只填入待确认表单。

文件：index.html 布局、styles.css 响应式样式、app.js 交互与持久化、nutrition.js 数据和份量解析、vision.js 按需端侧识别、tests 营养计算测试、scripts/serve.mjs 本地服务器。

- [x] 营养核心：克重换算、常见单位、多食物文字解析、未识别输入提示；先写测试观察失败再实现。
- [x] UI：今日汇总、餐次日志、可修改估算草稿、食物库、自定义食物、手动营养目标、日期、饮水、导入导出。
- [x] 照片：真实开源食物分类模型随网站分发并按需加载，本地处理照片；明确模型局限，用户选择候选并确认克重后才入账；失败保留手动输入。
- [x] 验证：Node 单元测试、语法检查、桌面与手机真实浏览器关键流程，照片推理可用性检查。
- [x] 发布：新建当前已认证账户下公共 GitHub 仓库，推送源代码，启用 GitHub Pages，确认网站返回成功后提供网址。

边界：营养数值为常见参考近似值，不代表品牌检测数据；生熟状态分开；餐馆油盐及复合菜差异较大。Food-101 单主体分类不能测重量、拆解多食物或可靠处理所有中餐，不承诺识别精度。记录仅保存在当前浏览器，可导出备份；不调用付费 API。

Ruling：首次 Swin 模型加载实测带宽不足，替换为 9.4 MB MobileNet V2 模型与本站分发的 ONNX Runtime；减少体积和第三方站点依赖，代价为分类能力不同，维持实验性候选确认流程。

完成：14 项单元测试与核心浏览器流程通过；实际披萨样图返回披萨 83.6%；公开仓库与 Pages 已建立，最终模型资产发布后进行线上烟雾检查。
